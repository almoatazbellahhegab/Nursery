# Sprint 2 attendance feature increment

Status: active domain implementation only. Sprint 1 remains incomplete and unaccepted. FEAT-011 is the only active feature; its branch is `feat/FEAT-011-child-attendance`. No operational endpoint is exposed and no push is authorized.

## Implemented decisions

The Python attendance package proposes immutable basic check-in/check-out events and a next presence snapshot. It records child/branch/classroom/organization scope, the trusted actor, client occurrence time, server receipt time and version. All stored instants normalize to UTC; naive, future or out-of-order occurrence timestamps are rejected. Presence is not an absence/sickness/late classification.

Duplicate present transitions, checkout without presence and stale versions return safe domain error codes. Exact retries with a trusted receipt return the original event and historical response with `replayed=True`; the caller must not write that historical state over a newer state. Changed payloads cannot reuse an operation ID. Scope/expiry checks run before receipt or state details. Public errors contain no identifiers.

The verified grant is an internal typed input, not an authentication mechanism. A future adapter must establish identity, organization/branch state, authoritative membership/assignment and revocation before creating it. There is no HTTP body field that can grant access. A regression test confirms that `/api/v1/attendance` remains unavailable.
