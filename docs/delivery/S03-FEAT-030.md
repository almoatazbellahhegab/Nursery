## Current implementation

An isolated Python domain module represents the nine product stages using opaque lead, organization and branch identifiers, without family names, contact information or child identity data. It proposes immutable state/history pairs with previous/new stage, trusted actor, UTC time, version, operation ID and workflow policy reference.

There is no default transition matrix. Every allowed move, including skipped/reopened stages, must have an exact edge in explicit trusted configuration; tests use a synthetic matrix. Empty policy denies all stage moves. A UUID/reference is not proof of approval: the future configuration adapter must enforce approval ownership and required-field/loss-reason conditions. A product clarification is pending.

The engine rejects other organization/branch/lead context, expired grant, stale version, no-op, undefined transition, naive time and backwards history. It checks scope before revealing state/policy conflicts. Direct stage editing cannot enter or leave ENROLLED; a future atomic enrollment workflow must coordinate lead conversion and child/guardian onboarding. This guard does not implement conversion.

The grant is trusted internal input, not authentication. The future server must resolve active organization, branch membership, action permission and revocation. No admissions HTTP endpoint exists; a fail-closed transport regression verifies that write attempts return 404.
